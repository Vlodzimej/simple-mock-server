# Simple Mock Server

Универсальный HTTP mock/proxy-сервис для тестирования. 
Работа сервера осуществляется через сессии. Каждая сессия знает адрес основного сервера, куда пересылает все запросы, кроме тех запросов, которые подменяются. Содержит состояния сценария и изолированный журнал. 

Управление доступно через Web-панель, HTTP API и MCP. 

## Требования

- .NET SDK 10 (версия зафиксирована в global.json).
- Node.js 24 и npm (версия Node указана в web/.nvmrc).
- Доступ к NuGet/npm при первой установке.

Backend: ASP.NET Core, EF Core и SQLite. 
Frontend: Angular 21.

## Запуск

Из корня проекта:

```bash
dotnet restore
cd web
npm ci
cd ..
./scripts/dev.sh
```

Панель: [localhost:4200](http://localhost:4200). Backend: [localhost:5080](http://localhost:5080). Ctrl+C останавливает оба процесса.

Раздельный запуск:

```bash
dotnet run --project src/MockServer.Api --no-launch-profile
```

В другом терминале:

```bash
cd web
npm start
```

## Собранная версия

```bash
./scripts/build.sh
cd dist/server
dotnet MockServer.Api.dll
```

Панель и API работают в одном процессе на [localhost:5080](http://localhost:5080). Для публикации нужен SDK, для запуска достаточно .NET 10 Runtime с ASP.NET Core. Запускайте из dist/server для предсказуемых путей к БД, настройкам и статическим файлам.

## Docker

Контейнер слушает `0.0.0.0:5080`. Compose публикует этот порт на всех интерфейсах хоста.

```bash
docker compose up -d --build
```

Панель и API: `http://<адрес-хоста>:5080`. SQLite хранится в томе `mock-data`. Пользовательской авторизации нет: опубликованный порт доступен любому, кто может открыть его по сети. Чтобы сервис отвечал на статическом публичном IP, этот адрес должен быть назначен хосту или маршрутизироваться на него, а входящий TCP 5080 должен быть разрешён файрволом хоста.

## Работа с сессией

1. Откройте панель и создайте HTTP-сессию.
2. Укажите название, `upstreamBaseUrl` и правила `rules`.
3. Сохраните и возьмите адрес подключения приложения: `/s/{id}`.
4. Используйте этот адрес как base URL; путь API добавляется после него.
5. Проверьте журнал, переключите состояние или сбросьте сессию для повторного прогона.

Маршруты и ответы определяет пользователь. Можно сопоставлять method/path/query/headers/form/JSON, задавать статус, задержку, заголовки и тело. Путь может быть точным или содержать отдельные сегменты `{name}`. `protectedPaths` запрещает fallback для выбранных путей; неоднозначные совпадения дают диагностическую ошибку.

[Формат правил, HTTP API и подключение мобильных устройств](docs/http-sessions.md).

## MCP для агента

Endpoint: `/mcp`, транспорт Streamable HTTP. Для Codex:

```bash
codex mcp add simple-mock --url http://localhost:5080/mcp
```

15 инструментов позволяют создавать и редактировать сессии/правила, переключать состояния, смотреть подробности и удалять записи журнала, проверять запросы, импортировать/экспортировать конфигурации. Агент и панель используют одну прикладную логику.

## Хранение и сеть

По умолчанию SQLite хранится в `data/mock.db` относительно content root процесса. Для постоянного расположения задайте абсолютный `DatabasePath`. Миграции применяются при запуске. Сессии, состояние и журнал переживают перезапуск. Журнал находится на отдельной вкладке сессии: поиск, фильтры, подробности запроса и ответа, удаление выбранных записей либо всего журнала без сброса состояния. Записи доступны страницами без ограничения общего количества; автоматического удаления старых записей нет.

Сохраняются query, заголовки и тела обеих сторон (до 256 KiB каждое), время, размеры, адреса, протокол, traceId и переход состояния. Известные секретные поля маскируются в заголовках, query, JSON, XML и формах. Multipart сохраняет поля и метаданные файлов. Усечённые или некорректные структурированные тела могут быть пропущены с объяснением. Сжатые тела gzip/br/deflate распаковываются с ограничением размера перед маскированием, неподдерживаемое кодирование пропускается. Бинарные тела сохраняются в base64; произвольные секреты в бинарных данных, тексте и путях автоматически распознать нельзя. Подробности появляются только у новых записей.

Один процесс сервера на одну БД. Для резервной копии используйте SQLite backup либо копирование остановленной БД с учётом WAL/SHM.

По умолчанию процесс вне Docker слушает loopback. Контейнер из `docker compose` слушает `0.0.0.0:5080` и публикует этот порт на всех интерфейсах хоста. Для телефона нужен доступный адрес компьютера и разрешённый origin приложения. Панель и MCP не имеют пользовательской авторизации; опубликованный порт доступен всем, кто может к нему подключиться. Остальные запросы действительно исполняются на выбранном backend.

```bash
dotnet test
cd web
npx playwright install chromium
npm test
npm run build
```

Браузерные тесты используют изолированный backend 5081, панель 4201 и отдельную SQLite в work. Интеграционные тесты работают с временными БД и локальным тестовым upstream.
