# Расширенный журнал: план реализации

**Goal:** Подробный сохраняемый журнал с фильтрами, страницами и удалением.
**Architecture:** SQLite хранит краткие поля и JSON подробностей. API списка не
возвращает тела, подробности загружаются отдельно. Курсор использует id записи.
**Tech Stack:** .NET 10, EF Core SQLite, Angular 21, Playwright.
**Spec:** ../specs/2026-11-25-request-journal-design.md

## Ограничения

Без новых зависимостей. Без ARIA. BEM sessions и requestJournal, inject() в полях.
Сохранение существующих сессий и журнала. Тела до 256 KiB. Маскирование секретов.

## Проверки рисков

Секреты вложенного JSON; усечённый JSON; сохранность проксируемого тела;
изоляция удаления по сессии; страницы при поступлении новых запросов.

## Задачи

- [x] Backend: тесты на захват, маскирование, фильтры, страницы, удаление и миграцию;
  `dotnet test` до реализации должен показать отсутствие новых полей/операций.
- [x] Backend: SessionRequestDetails и ограниченный захват потока; добавочная
  миграция DetailsJson/QueryString; интеграция в SessionDispatcher без усечения
  клиентского ответа. Фильтры в SessionStore.Requests, подробности и удаление
  через SessionAdmin; совместимые параметры MCP. Удаление предела хранения.
- [x] UI: Playwright на две вкладки, поиск и детали, загрузку следующей страницы,
  выбор и удаление с сохранением состояния. Затем RequestJournal с собственным
  API и формой фильтров; перенос журнала из Sessions с сохранением редактора.
- [x] Документация: новые поля, маскирование, API и пределы.
- [x] Проверка: `dotnet test`, Angular build, полный Playwright, контраст,
  обе темы, 320/820/1440 px и увеличение текста. Проверка diff и Delivery Gate.

Исполнение в текущем рабочем каталоге, без коммитов и изменения пользовательской БД.
