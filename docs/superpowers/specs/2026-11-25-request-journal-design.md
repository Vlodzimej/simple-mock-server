# Расширенный журнал сессии

Согласованный состав: query, заголовки и тела запроса и ответа, время, размеры,
upstream, сведения о клиенте, правило, причина результата и переход состояния.
Секретные значения маскируются. Каждое тело ограничено 256 KiB, усечение явно
обозначено. Текст отображается безопасной интерполяцией, бинарные данные в base64.
Старые записи сохраняются без выдуманных подробностей.

Журнал находится на отдельной вкладке выбранной сессии рядом с конфигурацией.
Фильтры: текст, метод, статус, источник, правило, период. Просмотр страницами,
без предела в 100 записей и без автоматического удаления после 5000.
Удаление: выбранные записи либо весь журнал, без изменения состояния сессии.

## Подход

Выбран серверный поиск с курсорной загрузкой и отдельной загрузкой подробностей:
все сохранённые записи доступны без загрузки всех тел в браузер. Альтернатива,
загрузка всего журнала и фильтрация в браузере, плохо подходит для больших тел.
Перехват ответа передаёт данные клиенту сразу и сохраняет ограниченную копию.
SQLite обновляется добавочной миграцией без удаления данных.

## Интерфейс

Направление из docs/DESIGN.md: ENERGY 1 / RHYTHM 1 / MOTION 1.
Существующие палитра, шрифты и отступы сохраняют узнаваемость рабочей панели.
Краткие строки запроса нужны для поиска ошибок, подробности раскрываются отдельно.
Нативные кнопки и поля обеспечивают клавиатурное управление без ARIA.
Подтверждение удаления называет конкретный объём операции.

## Границы

Маскирование известных имён секретных полей в заголовках, query, JSON, XML и формах;
неразбираемые JSON и multipart не сохраняются сырым текстом. Gzip/br/deflate
распаковываются до 256 KiB перед маскированием, другие кодирования пропускаются. В бинарных и
произвольных текстовых данных автоматическое распознавание всех секретов невозможно.
Сброс сценария по-прежнему очищает журнал, отдельная очистка журнала не сбрасывает сценарий.
